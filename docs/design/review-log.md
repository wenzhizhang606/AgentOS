本记录保存每轮设计更新后的来源复核、替代方案、问题修正和验证边界。当前任务只生成文档，开发、部署、协议互操作和基准试验均未开展。 [需求](../requirements/agentos-platform.md) · [技术设计](technical-design.md) · [运行契约](../specs/runtime-contracts.md) · [组件契约](../specs/component-contracts.md) · [验收](../specs/acceptance.md)

## 本轮约束与评价方式

已确定约束包括MySQL底层权威数据库、上下文管理优先、通用可插拔组件、多Agent、沙箱、安全围栏、RAG与MCP，以及只研究和审核文档。研究依据为10篇2026年7月起首发的arXiv论文、开源Agent的固定标签源码与滚动官方架构资料，以及MySQL、MCP和检索系统官方文档。源码版本和阅读范围分别记录在两份调研中。[论文记录](../research/arxiv-2026-h2.md) · [开源与技术选型记录](../research/opensource-agent-components.md)

评价依次检查需求覆盖、接口可互操作、授权与费用不变量、并发和恢复语义，再比较质量、时延、成本、兼容和运维复杂度。没有业务基准支持的选择标为候选。当前能判断方案是否满足已知约束及有无明显缺陷，不能由文献或文档审核证明跨所有场景全局最优。

## 方案取舍

| 决定 | 比较方案 | 当前判断及依据 | 改变决定所需证据 |
| --- | --- | --- | --- |
| MySQL为权威库 | 9.7 LTS新部署候选、8.4兼容基线 | 遵守用户数据库选择，依赖InnoDB事务能力，避免绑定HeatWave特有向量能力 | 驱动、备份、连接池及恢复演练的兼容结果决定实际补丁版本 |
| 检索使用独立适配器 | MySQL ngram、OpenSearch混合、Qdrant组合 | OpenSearch作为混合检索默认评测候选，MySQL词法作基线；权威状态与可重建索引分工明确 | 中文与代码召回、ACL过滤后效果、更新延迟和总运维成本 |
| 中台内核与Agent框架分离 | 深度绑定单一框架、统一契约接多框架 | 框架可复用循环、工具和上下文策略，中台持有身份、预算、发布与副作用账本；不同语言通过适配接入 | 端到端接入成本、框架升级兼容、强制治理覆盖和运行开销 |
| 初期持久队列在MySQL | MySQL队列、外部消息队列 | 少一套权威协调依赖，状态与Outbox同事务；队列公平性和根预算锁热点需测量 | 队列等待、锁竞争、吞吐或跨地域要求超出目标时引入消息系统 |
| 分层沙箱后端 | 受限进程、容器、gVisor或microVM | Profile明确所需隔离，后端声明并实测实际能力，不能把“容器”当统一安全等级 | 隔离测试、启动时间、资源成本、GPU/浏览器兼容与运维能力 |
| 围栏与执行授权分层 | 只依靠模型风险评分、规则与检测器加执行约束 | 模型用于信号，动作权限和资源限制在真实执行入口强制；参考编码Agent暴露的覆盖边界 | 攻击与良性集效果、误拒率、额外延迟及各通道覆盖 |
| MCP版本独立适配 | 只支持旧版、混用新旧状态、独立兼容层 | 2026版无旧初始化/协议session，故不能共用不区分版本的连接状态机 | 客户端和服务器逐版本互操作矩阵、维护成本及实际接入分布 |
| 稳定组件加有界增强 | 固定RAG、迭代证据研究器、自动改写Harness | 先建立统一评测、来源与预算，再启用增强上下文和RSI候选，保留固定基线 | 独立留出任务的质量与总成本、恢复成功率和新会话泛化 |
| 恢复采用效果范围与版本检查 | 全量快照覆盖、范围恢复、领域补偿 | 保护合法后续修改，无法安全合并时显式冲突；EvoUndo反向证据支持可恢复状态优先确定性方案 | 恢复用例、并发修改、误恢复和领域补偿结果 |

数据库与检索依据包括[MySQL版本策略](https://dev.mysql.com/doc/refman/9.7/en/mysql-releases.html)、[锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)、[向量函数边界](https://dev.mysql.com/doc/refman/9.7/en/vector-functions.html)及[OpenSearch混合检索](https://docs.opensearch.org/latest/vector-search/ai-search/hybrid-search/index/)。框架与协议取舍可回溯到开源调研的对应原始来源。

## 已修正的实质问题

| 问题 | 修正后的契约 | 验收关联 |
| --- | --- | --- |
| 历史记忆可绕过只撤回active修订 | 记忆级墓碑覆盖全部修订、历史ID及旧快照，恢复不能清除墓碑 | AC-006、AC-012、AC-017 |
| 恢复旧快照可能覆盖合法新变更 | 范围、前后版本、CAS和领域补偿；无法合并时保持现状并报冲突 | AC-011、AC-020 |
| 预签名直读绕过后续撤权 | 受保护内容经鉴权代理，重新读取和Range请求都检查当前权限 | AC-012、AC-020 |
| 准入与外部发送被误当原子 | DispatchAttempt提交为线性化点，稳定策略头与祖先取消状态参与事务；已准入在途单独记录 | AC-008、AC-012、AC-017 |
| 同一业务操作的重试费用可能漏记 | 业务operation、实际dispatch attempt、provider receipt三级区分，每个收费尝试分别预留 | AC-009、AC-013 |
| 取消或预算耗尽误停必要清理 | 独立控制面维护通道、执行侧硬租约、费用计到实际释放 | AC-020、AC-028 |
| 发布前检查无法阻止跨系统竞态 | 外置索引不可变暂存代次，MySQL按来源版本与墓碑CAS发布清单 | AC-005、AC-017、AC-024 |
| 灾备和历史检索承诺不明确 | 恢复水位与日志缺口隔离；RAG普通查询当前版本，历史证据按ID和版本显式读取 | AC-017、AC-024 |

额外核验依据为[S3预签名有效期与重复使用](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)、[MySQL备份恢复](https://dev.mysql.com/doc/refman/8.4/en/recovery-from-backups.html)、[OpenSearch索引可见性与版本](https://docs.opensearch.org/latest/api-reference/document-apis/index-document/)和[MCP HTTP取消及请求元数据](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)。这些来源说明能力边界，修复机制属于AgentOS设计推导。

## R5至R7的取舍与验证范围

本轮详细证据见[语言与需求复核](../research/language-and-requirements-review.md)。Python主平台与C++主平台均可实现服务，选择前者依据团队技能、策略迭代和现有生态；新C++模块须以热点或既有本地资产证明价值。线程池仅用于已验证释放GIL的长计算，强终止使用独立执行单元。没有基准结果证明某语言已达到平台SLO。

保留28项REQ、28项AC、19项TASK及完整10类矩阵。P0为基础必备优先级，分M1–M3交付；模型/上下文/记忆各两实现仍为基础平台完成条件。上下文编译可同进程，严格准入继续读MySQL权威状态。快照元数据/语义摘要与正文留存、传输字节证据分离，完整评测仍需获准载荷。安全处理与业务恢复分母分开，原有质量、成本和延迟目标没有宣称实测达标。

CubeSandbox固定版本的闲置TTL不等于硬deadline，整机快照不覆盖外卷或平台事务，SDK失败不证明资源已回收。复审新增三项：未知provider ID的创建关联发现；full恢复前先封锁旧执行权限；网络更新跨层失败及重启后的策略代次核对。这些是AgentOS适配认证条件，尚未确认后端能全部满足，不能标为已实现。

R7结构检查覆盖15份Markdown、28项REQ、28项AC、19项TASK、全部相对文件链接、2个JSON示例及10个Mermaid代码块；没有应用实现文件。流程图补上可跳过检索/重排/压缩的路径，并人工检查控制含义。未进行Mermaid渲染与图形布局验收，未开展Python/C++性能、CubeSandbox部署、故障注入或业务指标实验。

## 2026-11-18 · M1 代码静态复核

## 2026-11-18 · 单次 Agent 运行的轨迹

复核了 M1 的领取事务、带尝试号的任务事件、能力记录和模型准入记录。只读取任务最新状态会使第一次尝试看起来也取得了重试后的结果。此次按已提交的领取事件识别实例，并将 worker 标识写入新领取事件，兼容已有的历史记录。授权沿用任务监控的元数据范围。需求、案例及交付任务分别为 REQ-OBS-001、AC-013、TASK-009。并发重领、数据库查询性能和浏览器交互的运行结果待统一验证。[实例轨迹变更规格](../changes/agent-run-trace.md)

## 2026-11-18 · 模型和检索的部署配置

复核了模型网关接收的完整端点、固定发布清单及内置词法检索和检索 Tool 的输入。发布 ID 应反映实际参与请求、费用和候选选择的配置，API 与 worker 必须配置一致。模型密钥沿用 worker 的独立凭证路径。检索条数同时受 Tool 声明上限约束，阈值作用于当前词法分数。关联 AC-002、AC-010。真实供应商输出与特定业务语料的检索质量由部署方另行验收。[参数与配置优先级](../changes/model-rag-environment.md)
