# AgentOS 企业级 Agent 中台需求草案

2026 年 11 月 17 日 · 第五版草案 · 第一性原理复核与 Python / C++ 分工

## 我对需求的理解

AgentOS 是以**上下文管理为核心**的企业级 Agent 中台。它在每次模型调用前，依据任务、当前步骤、身份和预算，组织 Agent 所需的指令、业务资料、历史记录、记忆、工具信息和其他 Agent 的成果。业务团队使用中台提供的可插拔基础能力，构建单 Agent 或多 Agent 应用。中台统一管理模块、版本、授权、评测和运行证据。

例如处理一项售后问题，协调 Agent 可委派订单 Agent 查询授权订单数据，知识 Agent 检索适用政策，再由汇总 Agent 结合证据形成答复。每个参与者获取自己任务所需、且有权读取的上下文，返回结论、依据及未解决事项。业务团队可以分别替换检索器、记忆实现、模型或协作策略。任务完成情况、信息交接和成本由中台追踪。

已明确的方向包括统一基础能力、模块可插拔、上下文管理优先、多 Agent 协作，以及量化评价。**底层权威数据库使用 MySQL**。中台组件须覆盖各种 Agent 的构建需要，包含执行沙箱、安全围栏、RAG、MCP、人工介入、工作空间、事件和多模态输入输出。DeepSeek Harness 与开源编码 Agent 提供模块边界和运行机制参考，RSI 用于探索能力持续改进。当前任务只产出和审核文档，不生成应用代码。指标门槛和性能条件是待验证建议。 [企业平台调研](../research/enterprise-agent-platforms.md) · [开源实现与技术选型核查](../research/opensource-agent-components.md)

## 第一性原理与建设边界

平台的基本产出是在权限、资源和时效约束内完成业务任务，并能说明其依据和成本。上下文管理负责提供当前决策需要的信息；RAG 是获取证据的手段，记忆是可修订的信息积累，任务状态和业务权威事实各有自己的权威来源。无需模型判断的步骤允许直接使用确定性工作流。多 Agent 和 RSI 是可选执行与改进机制，使用收益通过对照评测判断。

统一管理要求统一身份、版本、来源、预算、准入和审计语义。上下文编译可以与 worker 同进程，检索和记忆可独立部署；纯本地去重、排序和格式化不强制增加远程服务或数据库事务。新的受保护读取、外发、跨身份交接和副作用仍执行当前授权与准入契约。

可插拔以有独立变更理由的能力边界为单位。业务开发者默认选择经过认证的配方；内部算法可替换，但身份派生、账本、墓碑、取消和准入不变量不能被插件关闭。认证覆盖声明支持的版本组合、Profile 和运行环境，不能由两个插件各自通过测试推导任意组合都兼容。

团队已确认熟悉 C++ 和 Python。建议 Python 承担平台业务与策略，C++ 承担已有本地库集成和经测量确认的计算热点；技术分工不改变用户能力契约。具体依据和修订理由见[语言选型与需求复核](../research/language-and-requirements-review.md)。

## Agent 类型与组件覆盖

类型由能力组合表达，一个 Agent 可以同时属于多种类型。每个 Profile 声明所需能力、模型输入输出模态、工具、执行隔离、记忆策略、交互方式和评测模板。接入新类型时扩展能力契约并增加代表案例。

| 类型 | 需要的中台组件 | 代表验收场景 |
| --- | --- | --- |
| 对话、知识问答与客服 | 会话、RAG、结构化查询、记忆、引用、人工转接 | 多资料回答及事实更正 |
| 深度研究与规划 | 搜索、浏览、固定有界多轮研究、计划、长上下文、报告产物；P1增加自适应证据研究器 | 基础认证验证受预算约束的多轮证据综合，增强能力另验 |
| 编码与软件维护 | 仓库检索、工作空间、文件编辑、终端、测试、补丁与审查 | 隔离分支修改、运行测试、形成可审查差异 |
| 数据分析与科学计算 | 只读数据连接、SQL工具、代码执行、资源配额、表格与图形产物 | 授权数据查询和可追溯分析报告 |
| 浏览器与桌面操作 | 浏览器或远程桌面执行器、独立会话、截图、动作策略、人工接管 | 读取页面与受控提交操作 |
| 企业流程与业务操作 | 确定性工作流、业务工具、审批、幂等和补偿 | 审批后执行一次业务动作 |
| 多 Agent 与组织协作 | 委派、依赖图、角色、共享证据、隔离上下文、根预算 | 并行分析后汇总与部分失败处理 |
| 长期自治与事件 Agent | 事件/定时触发、持久状态、记忆、预算周期、租约与恢复 | 重启后继续执行并正确停止 |
| 多模态与实时交互 | 模态适配、媒体产物、双向流、打断、背压和流式围栏 | 音视频输入转任务，取消后无旧动作启动 |
| 外部专业 Agent 与设备控制 | Agent协议、远程执行适配、能力和权限映射、外部状态核对 | 对接专业系统并说明可观测与可控制范围 |

设备、专业应用和企业连接器通过适配器接入。每个 Profile × 版本 × 环境记录 planned（待建设）、experimental（隔离实验）、certified（已认证）或 unavailable（已停用）。只有 certified 组合进入生产路由；experimental 需要独立实验入口、身份和预算。当前全部为 planned。目录完整度、已认证类型覆盖率、单个已发布 Profile 的能力通过率分别报告，禁止用缩小声明范围掩盖未完成类型。

## 功能需求

### 上下文管理

上下文管理贯穿模型调用、工具调用、任务恢复和 Agent 间交接。平台应能解释一次调用用了哪些信息、信息来自哪里、为何被选中或排除，以及哪些信息因预算被压缩或延后读取。

| 能力 | 建设要求 |
| --- | --- |
| 统一信息表示 | 为资料片段、工具结果、记忆和 Agent 产物记录来源、内容版本、时间、作用域和访问权限。将业务指令、用户约束、外部资料和推断结果标明类型。摘要保留原始来源引用。 |
| 按任务和角色选取 | 根据任务目标、子任务、身份、已完成步骤和可用工具选择上下文。支持按需检索和追问补充材料，明确显示证据缺口和冲突。 |
| Token 预算与组装 | 为指令、任务状态、历史、资料、工具定义分配预算，并预留输出空间。按相关性、时效性和任务需要排序，去重后组装。切换模型时重新计算其窗口和能力约束。 |
| 压缩与恢复 | 历史压缩保留目标、用户约束、已执行动作、未完成事项、有效审批引用和证据。大体积结果可保存为产物，通过引用按需加载。恢复时可重建任务状态并重新检查权限。 |
| 多级作用域 | 支持企业、项目、用户、会话、任务和单个 Agent 的数据范围。共享由显式权限与发布规则决定，子 Agent 在委派授权范围内工作。 |
| 一致性与时效 | 记录本次调用使用的资料和状态版本。更新、删除、撤权后处理关联缓存、摘要和索引的失效。对冲突事实保留来源和有效时间，权威业务状态按需实时查询。 |
| 调试与回放 | 每次调用保留授权的输入清单、语义摘要、版本和发送绑定；正文可完整保留、脱敏或仅留元数据。只对仍有完整授权载荷的记录声明输入重建，脱敏视图不冒充原始输入。质量评测使用获准完整留存的隔离数据。外部实时数据和模型随机性在结果中注明。 |
| 可替换策略 | 资料接入、切分、查询构造、检索、重排、去重、压缩、记忆提取及上下文组装均有独立接口和版本。替换后运行兼容性与质量回归。 |

分层记忆和压缩策略采用可评测的默认实现。原始事件、摘要和实体事实通过来源链关联，在预算允许且信息缺失时取回原始证据。压缩后对必保留项进行检查，无法容纳必要约束时返回明确的预算不足状态。探索型候选可以改进这些策略，其收益须与固定实现对照。

### 借鉴 RAG 的知识获取

1. 接入文档和现有业务数据服务，保存文档结构、版本、生效时间及权限。切分时保留标题、父文档与段落位置，处理更新和删除。
2. 支持结构化精确查询、关键词检索和向量检索。可组合召回并重排，选择策略和候选数量由评测结果决定。
3. 检索结果进入上下文前完成权限与有效性检查。需要调用外部重排服务时，先按该服务获准处理的范围过滤。
4. 把检索到的候选、最终送入模型的证据和回答引用逐级关联，分别定位检索遗漏、组装丢失和证据使用错误。
5. 对缺少依据、版本冲突和已过期资料，允许补充检索、请求澄清或给出有边界的答复。外部资料保持数据身份，工具执行仍由授权机制检查。

混合检索、为片段补充文档背景和重排有工程参考。具体收益需要用项目语料验证。 [Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)

### 多 Agent 协作

| 能力 | 建设要求 |
| --- | --- |
| 角色与能力注册 | 为角色定义职责、输入输出约定、可用工具、模块组合、上下文策略及权限。一个 Agent 的版本可以被多个协作流程复用。 |
| 任务分解与调度 | 支持协调 Agent 委派子任务、按依赖串行执行、并行执行后汇总，以及将任务控制权交接给另一角色。首期验证委派、并行和汇总，交接场景随业务需求补齐。 |
| 委派上下文 | 下发目标、交付格式、完成条件、必要证据引用、约束、预算和截止时间。子 Agent 使用独立工作上下文，按授权显式读取共享任务资料。 |
| 消息与成果 | 消息关联发送方、接收方、任务、版本和处理状态。结果包含结论、证据或产物引用、完成状态和待处理事项，汇总时能定位原始来源。 |
| 共享状态 | 任务进度和共享产物有明确所有者及版本。并发写入通过冲突检测或约定的合并规则处理，重试和重复消息保持幂等。 |
| 运行控制 | 控制总任务预算、并发数、委派深度和交互轮次。支持超时、取消、重试、子任务替换与恢复，明确部分失败时继续或终止的条件。 |
| 权限与隔离 | 子 Agent 权限受委派范围约束，跨 Agent 读取仍重新鉴权。停用任务可阻止新的派生任务及后续受管工具调用。 |
| 观测与优化 | 展示父子任务、消息、上下文来源、调用和费用，统计交接丢失、重复工作、等待及汇总错误。协作策略作为可替换模块参与评测。 |

多 Agent 的交接同时包含可供模型阅读的结论和供平台处理的结构化状态。事实修订或权限撤销会使依赖旧内容的交接产物失效。汇总者检查来源版本和未完成项，再决定补取证据、重做子任务或返回部分完成说明。共享记忆的授权覆盖精确读取、语义检索、缓存和派生内容。

### 创建、组装和复用 Agent

- 中台提供一套可运行的默认组合，业务团队可从模板创建 Agent，按需修改 Prompt、工具、技能和模块配置。
- Agent 的各模块通过明确接口进行组合。模型适配与路由、Agent 循环与协作编排、上下文与 Prompt、工具与技能、会话与记忆、执行与审批、观测与评测均应支持替换实现。首期重点验证上下文策略、模型及记忆实现的独立替换。
- 模块登记时记录接口版本、依赖、所需权限及状态兼容性。发布时校验组合并记录实际采用的模块版本和配置，使每次运行可追溯到完整的发布版本。
- 更换持久化实现时，已有会话可通过兼容读取或显式迁移继续使用。首期建议在发布版本边界完成模块切换，运行中的热替换按具体场景再确定。

### 企业统一管理

- 维护 Agent 与模块目录。记录负责人、团队、环境、版本、运行入口及工具依赖。
- 支持测试、评测、发布、回退和停用。受管路径在实际调用时按发起人、Agent 身份、操作和资源范围执行权限。权限变化和撤销应在约定时限内生效。
- 把一次运行的 Agent 版本、涉及的模块、模型用量、工具调用、策略判定和结果关联起来。对外部运行时分别标注登记、观测和策略执行的覆盖范围。

### 记忆作为可替换模块

- 会话状态用于恢复当前任务。长期记忆支持结构化事实的精确读写，以及基于内容的语义检索。业务权威数据通过授权接口实时查询。
- 区分业务系统观测、用户陈述、推断偏好、事件摘要和经验候选。相关性分数不提升事实权威性；业务接口不可用时，旧记忆只作为带观察时间的历史信息或触发澄清，不能冒充当前订单、库存或权限状态。
- 显式确认的事实和从历史归纳的偏好保留各自的来源与确认状态。语义记忆的提取、合并可以异步执行。
- 记忆按授权范围读写。支持更正、删除和保留期限，并同步处理派生索引。结构化存储、语义检索后端和记忆写入策略可独立替换。
- Fashion Mind 关联视频作为待核验线索，当前设计另参考已核验的 Google Cloud Memory Bank 文档。短链落点、官方视频正文和具体源码尚未确认，具体存储和产品选型留待验证。 [Fashion Mind 短链](https://g.dev/ai/fashion-mind) · [关联视频线索](https://youtu.be/8C4bh59FtsI) · [Memory Bank 技术文档](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/memory-bank)

### Agent 能力持续改进

- 平台保存可授权使用的执行轨迹、上下文选择记录、评测样例和版本结果，便于定位检索遗漏、压缩丢失、交接失真及协作错误。
- 后续可让优化 Agent 根据这些证据生成模块或配置候选，先从 Prompt、技能示例、上下文组装或记忆提取策略开始。候选应关联父版本、变更内容和试验结果。
- 独立评测用留出样例比较任务成功率、工具调用正确性、成本、延迟和权限行为。候选通过发布流程后可以成为下一轮基线。涉及持久状态时，分别验收配置回退和数据恢复。 [PluginRSI](https://arxiv.org/abs/2609.32423) · [Harness²](https://arxiv.org/abs/2610.14224) · [EvoUndo](https://arxiv.org/abs/2608.28363)

优化器对模块实现、配置和组合分别提交候选，评测先检查接口与状态兼容，再运行组件用例和端到端业务任务。原始运行快照、候选差异、评估预算及发布记录一起归档。恢复验收记录受影响状态和实际恢复结果，涉及已完成的业务写入时按领域操作执行补偿。

## 建议的首期范围

选择一个包含文档检索、结构化查询和跨会话信息的只读场景，提供单 Agent 和协调者委派两个专业 Agent 的实现。先验证上下文选取、权限过滤、压缩恢复、共享成果和记忆更新，再验证模块替换及可量化收益。业务场景可用售后政策与订单综合查询，最终由实际数据和使用者确定。

首期完整范围包含上述通用组件、MySQL持久化、上下文、知识与记忆、多Agent、沙箱、围栏、RAG与MCP服务接口、编码及其他类型代表场景、观测和版本发布。只读售后是第一个纵向切片。P1验证增强上下文策略，P2验证自动优化候选。首期采用发布版本边界切换模块的设计假设，运行中热替换按具体状态兼容能力扩展。

## 量化评价与验收建议

以下数值是供讨论的试点目标，实际结果尚未测得。先用开发集建立基线、确认场景难度与资源预算，再确定门槛并冻结最终验收集。确定性不变量（授权、幂等、账本、能力声明）必须逐例通过；质量收益与性能 SLO 按 Profile 冻结；诊断指标先报告基线。三类分别判定，不能用平均得分抵消硬约束失败。所有比例保存分子、分母和适用范围，零分母记不适用，不能填100%。

### 上下文与知识质量

| 指标 | 计算口径 | 试点目标建议 |
| --- | --- | --- |
| 证据召回率@10 | 在固定的单次检索评测集中，每个可回答问题的前10个检索片段覆盖的标注证据单元数 ÷ 所需证据单元数，再对问题取平均。等价来源归同一证据单元，重复命中计一次 | ≥90%，分别报告精确查询、多资料和长历史任务 |
| 任务累计检索证据覆盖率 | 整个任务中全部检索轮次和子 Agent 获取的去重必要证据数 ÷ 任务所需证据数，再对任务取平均 | 诊断指标，记录累计片段数、Token 和预算，在下项不足时定位获取阶段问题 |
| 最终上下文证据覆盖率 | 在预先选定的回答或动作决策点，模型实际收到的上下文正确保留的必要证据数 ÷ 该决策所需证据数。先按任务内决策点平均，再按任务平均 | ≥90%，与检索结果逐级对照。保留原文或正确提取的事实及可追溯来源可计入，只有链接的条目需实际取回后计入 |
| 压缩及交接保真率 | 压缩后或交接后的内容正确保留的关键事实与约束数 ÷ 压缩前或交接前标注的必保留项数 | ≥98%，压缩、交接各自统计。权限、审批、任务完成状态等关键字段专项用例全部通过 |
| 回答证据支持率 | 在需依据资料回答的任务中，被生成答案的模型实际收到且授权、版本有效的上下文支持的可核验断言数 ÷ 全部可核验断言数。子 Agent 摘要须能追溯至其实际接收的原始依据 | ≥95%，同时报告任务成功率，空答案记为不适用并进入任务失败统计 |
| 引用正确率与完整率 | 正确率为确实支持所关联断言的引用数 ÷ 全部引用数。完整率为带有效引用的需举证断言数 ÷ 全部需举证断言数 | 两项均≥95%，对来源版本和权限同时检查 |
| 记忆更新准确率与无依据处理 | 更新后正确采用有效新事实的任务数 ÷ 更新类任务数。无依据时正确澄清或表达未知的任务数 ÷ 无依据任务数 | 更新准确率≥95%，无依据处理正确率≥90%，另外统计有依据任务被错误拒答的比例 |
| 上下文 Token 降幅 | 1 − 候选方案平均每任务累计输入 Token ÷ 基线平均每任务累计输入 Token。包含所有子 Agent、重试、压缩、查询改写及异步记忆处理调用，统计至关联后台作业完成 | 目标降低≥20%，同时要求任务成功率下降不超过2个百分点，按后文的质量非劣标准验证 |

证据单元按固定原始文档段落或业务事实标注，记录全部可接受的等价依据。切分策略变化后沿用这些标注。动态检索通过任务累计覆盖率评价，单次检索的@10始终限定10个结果。无依据问题在召回率指标中标为不适用，单独评价处理正确性。RAGAS 和 ARES 提供检索与生成质量评价参考，长期记忆类别参考 LongMemEval。自动判分先用人工标注样本校准。 [RAGAS](https://arxiv.org/abs/2309.15217) · [ARES](https://arxiv.org/abs/2311.09476) · [LongMemEval](https://arxiv.org/abs/2410.10813)

### 任务效果与协作收益

| 指标 | 计算口径 | 试点目标建议 |
| --- | --- | --- |
| 端到端任务成功率 | 在规定时间及总预算内满足预先约定的业务完成条件的任务运行数 ÷ 全部启动的评测任务运行数。超时、预算耗尽和技术错误计失败 | 选定场景≥85%，并按任务类别公布 |
| 多 Agent 成功率增益 | 多 Agent 成功率 − 使用同一上下文能力的单 Agent 成功率。采用相同任务、模型版本和每任务总费用及截止时间上限 | 可并行复杂任务子集提升≥5个百分点，配对差异95%置信区间下界大于0才判定收益已获支持 |
| 单位成功任务成本 | 所有已启动任务的模型、检索、重排、工具、运行及后台记忆处理成本合计 ÷ 成功任务数 | 满足质量非劣标准时相对基线降低≥20%，或在相同费用上限下达到前项质量增益。两种验收路线在测试前选定 |
| 故障后业务恢复率 | 在测试前标为可恢复且预留充分恢复时间/预算的故障中，恢复后满足原业务完成条件且无重复副作用的运行数 ÷ 该类注入运行数 | 初始目标≥95%，逐类报告；不能在看到失败结果后将其移出可恢复集合 |
| 故障安全处理符合率 | 按预定规则完成恢复、拒绝、终止或进入受监控核对状态，且无越权、重复副作用及状态复活的用例数 ÷ 全部注入用例数 | 确定性专项用例100%通过；安全终止不计业务成功，外部结果未知不能标为已恢复，核对另受截止与告警约束 |

成功数为零时，单位成功任务成本记为无穷或不适用，同时保留全部费用。成本用统一价格表计算并记录币种、价格日期、缓存规则与费用覆盖范围。异步记忆提取、合并、写入和索引更新按任务归集，跨任务共享费用按预先固定规则分摊，并计入总预算。离线评测、数据标注、初次索引、持续索引维护、存储和 RSI 搜索费用另行列示，项目总成本去重汇总这些费用。配对比较包含全部失败和重试。

效率优化的质量非劣标准为候选减基线的任务成功率差，其任务级配对95%置信区间下界至少为−2个百分点。满足该条件后再判断 Token 或成本降幅，样本不足时标为待验证。单独更换更弱模型的结果在模型选型实验中报告。

多 Agent 增加以下诊断指标，用于解释收益和失败。首轮建立基线，暂不为这些指标设置通用门槛。

| 指标 | 计算口径 | 用途 |
| --- | --- | --- |
| 协调等待占比 | 根任务关键路径上因委派、等待成果和汇总协调产生的时间区间并集 ÷ 根任务端到端时间 | 避免把并发分支耗时简单相加，识别协作抵消并行收益的情况 |
| 重复工作成本占比 | 按预先标注规则认定的非必要重复检索、推理或工具操作成本 ÷ 全任务树成本 | 相同请求的必要重试单独标记，区分协作重复和容错成本 |
| 依赖死锁率 | 发生等待环或无可推进分支的永久等待、需终止或干预的任务数 ÷ 启动的协作任务数 | 分报环检测拦截、运行期死锁和普通外部超时 |
| 错误充分判定率 | 策略声称证据充分但实际输入缺少必要证据的决策点数 ÷ 声称充分的决策点数 | 检验按需补取和跨 Agent 汇总的停止判断，零分母记不适用 |

### 性能与平台可用性

| 指标 | 计算口径 | 试点目标建议 |
| --- | --- | --- |
| 上下文准备延迟 | 从收到完整准备请求到上下文可供模型调用的时间，包含在线检索、重排和压缩，报告 P50、P95、超时率 | 在固定10并发、10万知识片段、单次可见历史不超过3.2万 Token 的初始压测条件下，P95≤2秒。附模型、存储和硬件配置，冷缓存及热缓存分别报告 |
| 端到端延迟 | 从接收业务请求到最终成功或失败的时长，另列成功请求的 P50/P95 和全部请求的超时率 | 普通知识问答 P95≤10秒，选定多资料协作任务 P95≤60秒，业务体验确认后调整 |
| 记忆更正与删除生效时间 | 从服务确认接收操作到自管在线查询、缓存及派生索引均停止返回失效内容的时间 | P95≤60秒，记录最慢值。在线撤权在后续读取时重新校验，纳入下一项测试 |

| 沙箱与出站边界 | 边界用例中成功越界次数，另报正常操作被误阻断次数 ÷ 正常用例数 | 指定测试集中越界0次；报告文件、进程、网络和凭证各类样本，误阻断先建基线 |
| 围栏效果 | 攻击样例达成未授权目标数 ÷ 攻击样例数；良性样例错误拒绝数 ÷ 良性样例数 | 冻结攻击与良性集分别报告。确定性授权绕过用例必须全部拦截，模型检测效果须实测 |
| 审批一致率 | 与有效审批绑定内容完全一致的执行数 ÷ 使用审批授权的执行数 | 100%，另测过期、重放、资源变化和并发答复 |
| MCP契约兼容率 | 通过的必需协议用例数 ÷ 已声明版本、传输及能力的必需用例数 | 每个发布组合100%，未实现的可选能力不能声明支持 |
| RAG索引新鲜度 | 从来源变更提交到新有效版本可检索的时间 | 报告P50/P95及最长滞后，试点P95≤60秒。授权和删除阻断不等待索引完成 |
| 编码任务有效完成率 | 满足固定业务条件且基线测试与新增验收通过的运行数 ÷ 全部编码任务运行数 | 先建基线，报告测试篡改、补丁冲突、部分成功和每次有效完成成本 |
| 沙箱资源收敛 | 截止后仍存活的孤儿资源数；从终止请求到确认释放的时间 | 指定故障集最终孤儿资源0个，清理P95初始目标≤60秒，失败必须可追踪 |
| MySQL与异步运行 | 队列领取P95、锁超时/死锁重试率、Outbox滞后P95、迟到回执未核对数 | 首轮测基线并按负载设SLO，预算重复结算及已确认状态丢失专项用例为0 |

沙箱启动与策略检查开销、媒体首个有效输出延迟、流式取消收敛时间另行按Profile报告P50/P95。实时与批量任务的体验门槛分别设定，不能沿用普通问答的统一延迟目标。

### 对照实验与数据集

| 实验 | 保持一致的条件 | 比较目的 |
| --- | --- | --- |
| 单 Agent 默认流程与单 Agent 上下文管理流程 | 相同模型、工具、知识与权限快照、任务和总体预算。默认流程使用固定检索及最近历史窗口 | 量化上下文选取、压缩与记忆带来的收益 |
| 单 Agent 与多 Agent | 共用上下文能力、模型版本、数据和总预算，多 Agent 的费用汇总到父任务 | 量化任务分解、并行与协作的收益 |
| 混合检索、重排、压缩和记忆的逐项实验 | 每次更改一个策略，其余模块版本及配置冻结 | 找到增益来源和性能回退原因 |

200个分层任务、每个配置重复3次仅作为成本与覆盖的规划起点，不构成统一验收样本量。先在与最终集隔离的 pilot 上估计基线、配对差异方差及任务内相关性，再按主要指标、最小有意义差异（含−2个百分点非劣界）、显著性和统计功效确定独立任务数；功效初始建议80%，最终测试前冻结。重复运行不能视作600个独立任务，子集结论按其自身有效样本量判断。

覆盖精确事实、多资料综合、长历史、事实更新、无依据问题和协作交接，另建权限、删除及故障注入专项集。加入证据位置与干扰信息扰动。主指标、次指标、多重比较规则和停止规则预先登记；最终集打开后不因区间不够有利持续加题，新增检验使用新留出集或事先设计的顺序检验。样本规划依据见[NIST样本量方法](https://www.itl.nist.gov/div898/handbook/prc/section2/prc242.htm)，本项目配对与聚类结构需单独估计。

开发集供检索配置、上下文策略和 RSI 优化使用。验证集用于有限次候选筛选，优化器仅获得预先约定的汇总反馈。最终验收集按客户、文档族或时间段隔离，固定知识快照、必需证据、允许动作、成功条件和评分规则，候选提交冻结后由独立评测执行。任务间恢复环境与初始记忆，跨会话测试仅在该任务规定的序列内保留记忆。根据最终验收结果调整方案时使用新的保留样本。评测记录任务调用次数、重复运行和 Token 三类消耗，优化器本身也有预算。

论文基准中存在按 Harness 敏感度筛选的任务。项目验收集按真实业务分布取样，同时保留敏感子集用于机制分析，报告两个集合的成绩。 [HarnessOpt-Bench](https://arxiv.org/html/2608.06301v1) · [Evo-Bench](https://arxiv.org/html/2608.09096v2)

结构化查询和动作结果优先用可执行规则核验，开放式答案可用模型评分并抽样人工复核。冻结判分器版本和评分 Prompt，报告人工判断一致率及评测覆盖率。判分器故障标为待评，补评完成后再判定验收。重复试验按任务聚合，采用任务级配对分析报告95%置信区间，保留同一任务内的运行相关性；存在共享客户或文档依赖时按更高层簇处理。区间不足以支持所声称收益时标为待验证，不能把“未检出差异”解释为等效。零次越权仅说明专项测试观察结果，不能由非随机攻击夹具估计生产事故概率。

平台记录关键事实的去向、查询与检索排名、最终上下文清单、每次模型用量、父子任务、重试、失败原因和评分证据，形成按版本、场景、租户及模块可查询的评测报告。

### M1 公开评测基准

REQ-EVAL-001、REQ-EVAL-002 和 AC-014 指定下列三项基准评价当前只读 Profile。涉及生成的运行统一设置 `AGENTOS_MODEL_NAME=gpt-6.1-sol`，经 AgentOS 任务 API、worker 和模型网关提交。检索专项直接调用当前发布的检索与排序路径，模型调用数应为零。当前状态为 `planned`，已有工程测试通过数与公开基准成绩分别记录。

| 基准与固定划分 | 输入和中台路径 | 主指标与诊断 |
| --- | --- | --- |
| **BEIR · SciFact test** | 导入完整 SciFact 语料，保留原始文档 ID，以每条查询取排序后的文档列表。评测配置将 Top-K 和 Tool 允许的上限均设为 10，保留少于 10 条及空召回的结果。 | 按官方相关性标注计算 **nDCG@10**，同时报告 Recall@10、空召回率和检索 P95 耗时。该分数评价检索顺序和覆盖。 [BEIR 官方数据与评分示例](https://github.com/beir-cellar/beir) |
| **HotpotQA · distractor dev** | 每题只导入官方提供的 10 段材料，保存标题及原句索引。通过只读任务回答，保留模型实际收到的上下文快照。 | 用官方评分器计算 **Answer F1** 和 Answer EM。另算快照涵盖的金标支持段落比例，定位召回或窗口裁剪造成的丢失。官方 Supporting Fact 和 Joint 指标要求预测句级证据，当前段落引用只支持段落诊断，这两项标记为不适用。 [官方任务与评分器](https://hotpotqa.github.io/) |
| **SQuAD 2.0 · dev** | 每题只提供指定段落。对成功回答，采用冻结的规则剥离平台引用标记后评分。对明确的 `MISSING_EVIDENCE` 记录触发阶段，分别统计检索无命中和模型明确返回证据不足。 | 按官方 **Exact Match 和 F1** 评分，按有答案、无答案两类拆分，并报告有答案题的误拒率。明确证据不足可映射为空答案。超时、鉴权失败、超预算和模型输出无效计技术失败，在项目全样本指标中逐题赋零。 [官方数据](https://rajpurkar.github.io/SQuAD-explorer/) · [官方评分脚本](https://github.com/rajpurkar/SQuAD-explorer/blob/master/evaluate-v2.0.py) |

在隔离评测项目中按样本 ID 配对运行冻结基线与候选，只更改被考察的检索或上下文配置。两组保持模型、问题、可见语料、提示、截止时间和预算一致。两项问答均保留原始回答，送交评分器前只剥离平台生成且可核验的引用标记，金标仅供评估器读取。按基准分别报告全量样本数、有效预测数、技术失败数、质量差值及其 95% 置信区间。生成类另报端到端 P95 延迟、输入输出 Token、按回执结算的总费用和待结算数。官方分保留原评分口径，逐题失败补零的项目结果单列。

TASK-010 首次运行前须冻结数据文件及 SHA-256、评分器提交、样本 ID 清单、代码提交、有效发布 ID、模型与价格版本，并准备数据导入、引用映射和预测导出适配。开发调参使用训练划分或独立开发样本。公开 dev/test 成绩用于工程回归，企业上线门槛继续使用隔离的业务留出集。[来源与适配说明](../research/m1-public-benchmarks.md) · [AC-014 验收要求](../specs/acceptance.md#ac-014-业务量化评测)
