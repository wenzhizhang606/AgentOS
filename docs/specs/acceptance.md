# AgentOS 验收规范

2026 年 11 月 17 日 · 设计基线草案 · 案例待实现与执行

每个案例以可观察行为定义完成条件。数值门槛、统计口径及试点条件以[需求文档](../requirements/agentos-platform.md)为唯一基线，字段与状态以[运行契约](runtime-contracts.md)为准。本文件中的预期结果尚未经过软件验证。

## 基础测试数据

测试夹具包含两个租户、同租户两个项目、不同读写权限的用户、委派身份、两个来源修订和一条跨修订更正链。每个知识片段有原文位置及 ACL。准备短历史、长历史、冲突事实、无依据问题、过期事实和相似但不相关资料。

多 Agent 夹具包含可独立并行任务、强依赖串行任务、共享状态冲突和部分失败。工具替身能够注入响应超时、已执行但回执丢失、重复回执和延迟回执。真实接口集成测试与工具替身测试分别报告，替身通过不代表外部系统具备幂等能力。

## 需求与案例

### AC-001 来源与实际输入

关联 REQ-CTX-001，对应 TASK-002、TASK-005。

给定原文、工具结果、记忆和子任务摘要，触发一次模型调用。检查网关最终语义输入中的每个受管条目均能追溯到来源版本、类型、作用域和选择原因，实际发送与快照语义摘要绑定。只创建未发送的快照不能统计为实际调用。缺失来源的外部事实不能作为已验证证据输入。

保存快照清单、留存策略、准入和回执；来源可追溯率按需求口径达到100%。分别验证full、redacted、metadata_only：完整载荷按原规则核验语义摘要，留存副本按自身摘要核验，脱敏/未留存/已删除时拒绝完整回放。注入SDK附加语义内容应生成新绑定，只有传输表示变化时保留语义等价；完全不透明适配器不能认证完整治理。普通日志不含输入正文，认证头不进入可选请求体字节记录。报告内容审计覆盖和完整回放覆盖，质量评测使用获准full留存的隔离样本。

### AC-002 上下文预算与证据组装

关联 REQ-CTX-002，对应 TASK-004、TASK-005。

对同一任务分别运行精确查询和混合检索，检查候选、最终输入和引用的逐级对应。必要约束、消息包装、工具定义及输出预留共同参与窗口计算。去重不能丢失不同版本或相互冲突的事实。

注入无法容纳必要约束的窗口，预期返回 `CONTEXT_BUDGET_EXCEEDED` 且不调用模型。接近窗口上限、空检索结果和计数器误差余量均有边界案例。报告召回率@10、最终上下文覆盖率、证据支持率和引用正确率、完整率。

### AC-003 压缩与恢复

关联 REQ-CTX-003，对应 TASK-005、TASK-006。

给定包含约束、既有动作、未完成事项及原文依据的长历史，压缩后检查关键项及来源，按需要回取原文。在任意完成步骤后中断 worker，以新租约恢复，任务状态和已完成逻辑动作保持一致。

分别注入原文被删除、来源撤权和压缩关键项丢失。预期按当前授权拒绝读取、标明不可回放范围，或回退原文及明确预算失败。不能承诺已删除载荷仍可完整重建。报告压缩保真、原文回取成功率和重复副作用，关键权限及完成状态专项案例全部通过。

### AC-004 按任务补取与策略比较

关联 REQ-CTX-004，对应 TASK-009、TASK-011。

给定初次检索缺少关键证据的任务，增强策略在限定轮次、费用和时间内补取，保留每次缺口与取用记录。分别得到充分、缺证据、预算耗尽三类终止结果。内部充分判定通过人工证据标签独立检查。

对照同一任务的两个策略快照，能够定位选入、淘汰和压缩差异。循环补取、无新增证据、依赖失败时在预算内停止。报告质量—成本—延迟曲线和错误充分判定比例，默认策略是否切换由预先固定的验收路线决定。

### AC-005 知识生命周期

关联 REQ-RAG-001，对应 TASK-004。

同一文档经历接入、重试、更新和删除，生成可追溯的片段与版本。当前查询采用有效版本，授权历史查询能定位旧版本。相同接入操作重复投递不增加重复片段。结构化业务查询保存授权及查询时间。

暂停旧版本索引作业，更新或删除来源后再恢复该作业，预期不能重新发布旧内容。关键词、向量、ID读取和缓存路径均不能越过当前权限。验证中文、表格和过滤后低召回的样例，并分报检索效果。

### AC-006 记忆修订与遗忘

关联 REQ-MEM-001，对应 TASK-006。

创建事实及派生摘要，随后提交更正、冲突候选和撤回。检查修订链、有效时间与头指针，更正后采用新事实，无法确定的冲突保留来源和状态。并发修订以同一预期版本提交，最多一个更新当前头，其余返回版本冲突。

撤回成功后同步读取检查权威状态，后台完成所有在线派生失效后记录传播结束时间。旧提取器作业、缓存和索引不能复活内容。删除原文、快照载荷及备份按各自保留策略检查，不能用在线清理完成代表备份已物理清除。报告更新准确率、无依据处理、错误拒答率及在线传播 P95。

分别注入旧订单观测与新业务结果、用户陈述与模型推断冲突、权威接口不可用。语义相关性高不能覆盖当前权威事实，接口不可用时不得将历史值当作当前业务动作依据。记录来源类别、有效期、历史标记与澄清结果。

### AC-007 委派与证据交接

关联 REQ-MA-001，对应 TASK-007。

协调者创建两个专业子任务，每个包含目标、完成条件、输出格式、授权引用、预算和截止时间。检查私有上下文隔离、按需读取共享结果，以及汇总结论到原始证据的来源链。

子任务返回完成文本但缺少必要产物、使用过期证据或有未完成条件时，汇总者应识别并按规则补做或标记部分结果。创建循环依赖或超过委派深度应拒绝。报告交接保真率、最终输入覆盖率和任务完成率。

### AC-008 并发、重试、取消与恢复

关联 REQ-MA-002，对应 TASK-003、TASK-007。

同时提交相同幂等键和相同请求，只创建一个任务或子任务。相同键不同载荷返回冲突。两个分支以相同预期版本修改共享产物，只允许一个提交，其余显式合并或重做。

注入 worker 失联后恢复，旧租约不能提交。并发完成、取消和超时由同一状态版本决定终态。取消后尚未准入的动作不能开始，迟到响应不复活任务。外部写结果未知时进入核对，不能盲目重发。按预先冻结集合分别报告故障后业务恢复率和安全处理符合率，列出注入次数、终态、重复业务副作用、核对截止和未解决项；安全停止不计业务成功。接入现有runtime时注入节点重放与双方断连，验证只有一个重试责任方、检查点不会回退平台账本或取消状态。

### AC-009 根预算与协作收益

关联 REQ-MA-003，对应 TASK-003、TASK-007、TASK-010。

让多个子任务同时预占最后一段可用额度，检查总预占加已结算不超过硬预算。同一逻辑操作的两次已收费尝试分别预留与结算，同一尝试的重复回执只结算一次，未知回执保留预留。重排、压缩、重试及异步记忆共享根账本。取消后停止待执行业务作业，清理、撤密钥、墓碑传播及费用核对继续收敛并计费。

在相同模型、上下文能力、根费用和截止时间上限下比较单 Agent、固定协作和动态协作。报告复杂可并行子集增益及置信区间，也报告完整业务分布效果。未达到统计支持时结论为不确定，单 Agent 路径继续可用。

每个hard_budget组合提交用量和费用上界的推导及环境假设，验证最大输入输出、重试、计费粒度、释放延迟和失联清理。无法证明实际可执行上限的后端不能仅凭账本预留通过该认证；实际账单与固定价格表分别核对。

### AC-010 模块替换与接口兼容

关联 REQ-MOD-001，对应 TASK-001、TASK-008。

M1 的配置绑定案例检查 API 与 worker 在相同配置下生成同一发布 ID，模型或检索策略的有效值变化后发布 ID 跟踪该变化。另检查密钥轮换、旧 JSON 回退和无效配置拒绝，以及检索条数和最低分对实际上下文候选的影响。[配置范围](../changes/model-rag-environment.md)

基础平台完成前模型、上下文和记忆各有两个实现，同一组接口及业务案例可替换执行，消费者不必修改业务逻辑。M1先验证一个真实实现与契约夹具，不能因此宣布本案例全部完成。检查输入输出、错误、取消、权限、计费及状态兼容；新增能力单独声明，复制代码或只改参数不能充当独立替换证据。缺少能力声明、不支持的接口主版本、无效 Schema 或无法执行的预算上限应在发布校验时拒绝或明确标记受限能力。

分别记录单模块替换结果与完整组合结果。验收标准是契约通过及业务门槛，不要求不同模型输出逐字一致。记录业务开发者从模板接入一个 Agent 的步骤与耗时。

两个组件分别通过但组合故障、版本别名变化、环境不匹配时，旧认证不得自动继承。实验组合不得进入生产路由；发布组合与关键交互风险均有报告。采用C++时增加金额精度、Schema非法值、所有权/大缓冲生命周期、并发调用、挂起/崩溃、取消及ABI升级案例，受控原生失败不能破坏MySQL权威状态。绑定与RPC分别计入复制、排队和端到端开销。

### AC-011 发布、迁移与恢复

关联 REQ-MOD-002，对应 TASK-008。

发布新插件组合后，新任务按灰度规则选择版本，旧任务恢复仍使用原组合。迁移失败时活动发布指针不指向未验证状态，保留旧读路径和检查点。已完成的兼容Schema扩展及可重入的部分回填可以保留，记录准确阶段并恢复推进，不能声称DDL已随业务事务回滚。

验证配置回退、范围快照恢复和业务补偿三类结果。先应用变更A，再产生合法变更B，通过范围与版本检查恢复A，B必须保留。若重叠变更无法安全合并，预期返回冲突并进入协调，不能覆盖B或虚报恢复成功。多初始状态、迁移中断、重复恢复和版本不兼容均有案例。记录恢复成功率、冲突率、未声明效果、误报及合法后续状态受损数。

### AC-012 统一授权与并发撤权

关联 REQ-GOV-001，对应 TASK-002、TASK-004、TASK-005、TASK-006、TASK-007。授权模块先独立测试，模型发送和跨Agent转发由后续集成任务验证。

使用跨租户、跨项目、子 Agent 越权和伪造身份字段测试检索、ID读取、缓存、摘要、快照检查、产物转发、外部重排和模型发送。有效权限由服务端身份与资源策略派生。

在准备快照后、发送准入前撤权，预期拒绝发送或重建。撤权提交之后的准入必须使用新版本。已经准入的请求记录顺序，返回投递重新鉴权。记录零越权观测目标与路径覆盖率，未发现越权不等同于形式化安全证明。

记忆级删除后，使用全部旧revision ID、历史时间查询、旧快照和迟到索引事件尝试读取。除按保留策略获准的审计元数据外，内容均不可返回，不能仅移除当前active修订。

撤权后重复使用此前获得的产物引用发起GET与Range请求，均经当前鉴权。已有在途下载按准入边界记录，不能以短URL有效期代替逐次授权。

### AC-013 观测与费用完整性

关联 REQ-OBS-001，对应 TASK-005、TASK-009。

从根任务查询完整子任务树、上下文快照、工具调用、重试和费用回执。随机抽样实际调用，按逻辑操作、发送尝试和提供商回执三级核对。重复回执不得重复计费，不同已收费尝试不能因属于同一操作而漏记。

任务执行已完成但后台费用未结算时显示 `accounting_state=pending`，全部核对后显示 `final`。未授权的观察者不能通过日志或快照检查读取敏感内容。报告追溯覆盖、未结算项和异步成本占比。

M1 实例轨迹案例使用同一发布版本的排队任务和被两次领取的任务。按 Agent 发布版本查询，断言运行列表有两条不同尝试，排队项没有运行记录。分别打开两条轨迹，核对领取、上下文、能力调用和该次模型回执归属。只有后一次成功时，前一次的轨迹保持其历史状态。普通用户、项目观察者及被撤权用户分别经目录、运行列表和直接 ID 查询，检查可见范围与敏感内容隔离。手动验证时可按[运行轨迹操作步骤](../changes/agent-run-trace.md)复现。

在一次已结束的运行中保留超过 500 条事件，含时间戳相同的事件。首次进入显示最近 500 条，随后逐页读取更早事件。核对各页均为时间升序，同一次尝试的事件无遗漏、无重复。

### AC-014 业务量化评测

关联 REQ-EVAL-001，对应 TASK-001、TASK-010。

M1 公开基准按需求指定的划分逐项验收。核对 SciFact 文档 ID 与排序、HotpotQA 的答案和快照证据、SQuAD 2.0 的明确拒答与技术失败映射。两项生成任务须记录实际请求的模型 `gpt-6.1-sol`，纯检索任务核对模型调用数为零。交付冻结清单、逐题预测和评分器版本，复算各组分母及配对差异。适配或数据缺失的项目记为待验证。[基准与指标](../requirements/agentos-platform.md#m1-公开评测基准)

按需求固定任务集、证据标签、预算、环境、重复次数及评分版本。全体已启动任务保留结果，技术失败、超时和预算耗尽按任务失败计入。判分器故障保留待评分并补评，不能删除困难任务。

同任务配对统计质量和成本，按任务簇计算置信区间。成功任务为零时单位成功成本标为不可有限估计。无证据题、空答案和不适用指标按需求口径处理。报告样本量、覆盖率、分层结果、冷暖缓存、费用结算及门槛判定。

核对独立pilot、功效估计、主要/次要指标、多重比较及停止规则在最终集解封前冻结。重复运行不能伪增独立样本，区间不足判inconclusive，不能在观察结果后持续补题直到通过。确定性、业务质量、性能SLO及诊断指标分别判定。

### AC-015 留出隔离与可复核配置

关联 REQ-EVAL-002，对应 TASK-010。

使用优化器身份尝试访问最终验收题目、标签、评分代码、凭证和日志，预期拒绝。数据按用户、项目、文档来源及时间隔离，重复与派生内容不得跨集合泄漏。验证集只能返回事先约定的信息。

候选、基线和实验配置摘要冻结后由独立执行者解封最终测试。更改候选使原结果不再适用。结果保存数据划分摘要、工具及模型版本、价格表、预算、缓存和随机性设置。最终集使用记录可审计，重复选择后的保留集需更新或降低结论强度。

### AC-016 受控候选改进

关联 REQ-RSI-001，对应 TASK-012。

优化器在固定资源预算内提出一个模块或组合候选，保存父版本、差异、来源、探测执行和采用理由。候选通过接口、权限、恢复、组件回归与端到端业务评测后，才能形成可发布版本。

候选尝试修改评测器、读取留出数据、扩大权限或超出优化预算时应被运行环境阻止。验证集提升但最终集回归或统计不足时不自动晋升。全部候选与被淘汰成本保留，按每次有效改进的总成本及后续回归率评价。

### AC-017 MySQL权威状态与派生索引

关联 REQ-DATA-001，对应 TASK-013。

在MySQL执行多worker领取、根预算并发预占、唯一键去重、死锁、锁超时、提交响应丢失和Outbox重复乱序案例。队列可以跳过已锁行，预算和权限不可跳过。数据库不可用时不放行新受管动作，提交结果未知按操作ID核对。事务整体重试不得重复外部副作用。

以旧副本、旧事务快照、滞后检索索引测试撤权和墓碑，准入仍由主库权威状态判定。重建索引及切换嵌入版本后不复活失效内容。分别验证固定规范化语义摘要与留存副本摘要，仅启用请求体捕获时验证wire_digest，不能从MySQL JSON重序列化推定原始字节一致。DDL按扩展、迁移、校验、指针切换与收缩分阶段，失败保留可读旧状态。

暂停旧索引作业于物理写入前，提交新版本或墓碑后恢复旧作业，预期其MySQL发布CAS失败且未发布内容不可读。暂停于最终准入前后分别触发撤权，核对线性化顺序及真实发送时间，不能把已经准入在途请求算成新的授权。

从早于一次撤权、外部动作与费用回执的备份恢复，分别提供完整binlog和缺口日志。完整路径核对后恢复，缺口路径保持受影响范围隔离。旧worker及工作区租约失效，不能依据数据库缺记录重发业务动作。报告实际恢复水位、RPO/RTO与未决项。

### AC-018 Profile能力覆盖

关联 REQ-AGT-001，对应 TASK-008、TASK-019。

为需求类型矩阵逐项创建代表Profile，校验所需模型模态、上下文、工具、执行器、围栏、交互和评测能力。每个必需能力有真实入口案例。将不支持图像、工具调用或沙箱隔离的后端配置给相应Profile，预期发布或路由明确失败，不能静默丢弃能力。

planned与experimental不能进入生产路由，认证绑定版本、环境和预先冻结的业务必需能力；停用后阻止新路由。报告单个已发布Profile通过率与完整10类矩阵覆盖，未完成类型保持分母可见。管理台/配置编辑服务中断而运行准入可用时，已固定发布任务可继续；权威准入不可用时拒绝新受管动作。

研究类基础Profile验证固定、有界的多轮流程；TASK-011交付的自适应补取作为额外能力按AC-004验收，不能用基础类型认证代替增强算法验收。

### AC-019 多模态与流式交互

关联 REQ-IO-001，对应 TASK-019。

验证文本、结构化数据、文件、图像、音频和视频引用的MIME、大小、摘要、权限及派生来源。转录/OCR失败明确呈现。测试慢消费者、背压、断线、重复增量、重连和实时打断，持久状态事件可去重恢复，旧执行代次不能启动新动作。

需要输出扫描的Profile先检查再投递，不能先泄露流式内容再标记拦截。报告首个有效输出、队列和取消收敛时延，展示层临时增量与权威事件分别验收。

### AC-020 沙箱与工作空间

关联 REQ-EXE-001，对应 TASK-014。

测试路径穿越、符号链接、保护文件、挂载、子进程、CPU/内存/磁盘/进程数上限及各类网络出口。记录后端和实际强制策略。沙箱不可用、策略无法实施或执行租约丢失时拒绝执行，不能回退宿主权限。

通过取消、硬超时、进程中断及回收失败测试工作区生命周期。检查点明确排除的文件、进程和外部动作不得标为已恢复，恢复遇后续合法修改返回冲突。最终孤儿资源和每条执行通道的策略覆盖可核对。

杀死worker后独立执行控制器仍按硬租约终止进程及受控网络，旧worker不能续期。业务预算耗尽后清理继续，费用统计至确认释放。对曾读取过产物的客户端撤权，再复用旧引用请求内容，鉴权代理必须拒绝。

CubeSandbox候选专项：持续心跳、长命令及WebSocket活动不能延长平台绝对deadline，晚到自动恢复被拒绝；未知provider状态不算清理成功。分别验证full/fs-only、共享外部卷、跨节点未ready和CPU/kernel不兼容。整机恢复不能覆盖合法后续写入或回退平台取消/费用/审批/墓碑；旧凭据和租约失效，必要时仅在新隔离工作区恢复。关联AC-011和AC-026，恢复后的测试证据必须重新绑定实际文件树。

在full快照中保留会自动发网络请求及写共享卷的进程，恢复前改变权限或取消任务，验证VM外门禁先检查并阻断直连/出站/共享写入，旧进程不能在重新授权前产生动作。后端无法提供该边界时拒绝该恢复能力认证。

### AC-021 安全围栏与强制准入

关联 REQ-GOV-002，对应 TASK-015。

分别经原生工具、MCP、技能脚本、浏览器、子Agent、外部运行时和结果投递触发相同策略。伪造只读标签、Prompt注入、参数Schema差异及模型自报低风险不能覆盖硬拒绝。授权、预算等强制检查不可用时一律拒绝受影响的读取与调用；仅非强制检测器可按Profile明确的规则降级，并记录覆盖缺口。

冻结攻击集与良性集，分别报告攻击达成率和误拒率，注明覆盖范围。检查模型、重排、浏览器与MCP流量不遗漏出站校验，检测器模型效果不替代操作系统或资源权限验证。

CubeSandbox组合另测未配置鉴权、回调故障、管理端口暴露、默认公网、局部网络更新重开公网、请求规则覆盖模板、直接IP/非HTTP与WebSocket升级后流量。发布前拒绝不符合Profile的配置；实际不支持的内容围栏能力不得宣称可用。

在CubeEgress更新后、CubeVS更新后及策略持久化前分别注入失败，再重启节点；期望代次未核对前维持隔离，旧持久策略不能恢复已撤销访问。分别检查已有连接、重新连接及DNS派生规则的实际处理。

### AC-022 MCP双向接入与兼容

关联 REQ-TOOL-001，对应 TASK-017。

平台分别作为客户端和服务器运行所声明协议版本与传输的必需用例。2026-07-28和2025-11-25按各自契约验证发现、版本、能力、调用和关闭，禁止在任意错误下静默降级。校验HTTP header/body一致性、Origin、audience、scope、过期凭据以及stdio的环境隔离。

发现的工具必须登记后调用。Schema漂移、名称碰撞、跨租户handle、伪造annotations和输出不符合Schema均有案例。断线后有副作用操作按平台操作ID核对，JSON-RPC ID不能代替幂等键。未声明的资源、Prompt、sampling或elicitation能力明确拒绝。

### AC-023 工具与技能登记

关联 REQ-TOOL-002，对应 TASK-017。

本地函数、HTTP、MCP工具和技能采用一致的内部身份、来源、能力及版本登记。动态工具变更不能绕过准入；工具隐藏不等于授权撤销，知道ID直接调用仍需鉴权。项目配置和技能文本要求扩权时不能自行获得能力，依赖或包摘要变化重新校验。

### AC-024 独立RAG服务

关联 REQ-RAG-002，对应 TASK-016。

通过业务API和获准的MCP接口分别完成资料接入、索引状态查询、检索、重排和证据解析，结果遵守同一来源、权限、版本和费用语义。比较MySQL词法基线与混合后端，测试中文、精确编号、表格、代码符号和过滤后召回。

索引滞后、嵌入维度或模型版本不匹配、解析部分失败、无依据及权限收缩均返回可辨识状态。不允许外部调用者通过自填tenant或filter扩大资料范围。记录召回、nDCG、零召回率、索引新鲜度和每次有效查询成本。

同源两版本先更正后撤回，普通查询仅取当前发布版本。明确指定仍保留的旧证据版本时返回历史标记和当前授权结果，撤回后历史ID也不可读。未声明的历史时间查询参数返回不支持，不猜测as_of语义。

### AC-025 人工决定与持久恢复

关联 REQ-HITL-001，对应 TASK-015。

暂停任务后重启worker，由获授权主体批准、拒绝或提交修改建议。重复答复与并发不同答复通过版本检查得到唯一有效决定。审批过期、参数变化、目标资源版本变化、策略撤权或任务取消后，旧审批不能执行动作。

无交互环境不能把需人工决定解释为允许。恢复路径仍执行授权、预算和幂等检查。记录审批绑定一致率、等待时长及恢复成功率。

首个发送尝试消耗批准后，同一操作合法重试必须核对consumed_by_operation_id、原摘要、绑定范围和有效期。操作变更、过期、撤权或绑定变化不能沿用已消耗批准，重新申请后才可继续。

### AC-026 编码流程

关联 REQ-CODE-001，对应 TASK-018。

固定仓库基线，在隔离工作区读取代码、生成补丁、应用、运行测试并输出差异。测试补丁全部成功、部分成功、原文hash变化、目标路径不匹配及用户已有修改。重复请求依据实际结果继续或报告冲突，不重复应用已完成部分。

测试命令、镜像、依赖、日志和用例范围可追溯，Agent改过测试需单独标记。生成、应用、测试、提交和推送分别鉴权。提交存在、命令退出0或单个测试通过不能替代业务完成条件。文件恢复不宣称已撤回远程推送或数据库写入。

### AC-027 外部Agent与框架适配

关联 REQ-INT-001，对应 TASK-019。

分别测试平台原生Profile和一个外部运行时适配器。外部能力声明、任务/消息响应、流式事件、产物、错误与取消映射到平台契约。不支持流式或取消的后端明确返回能力错误，不能模拟已经终止。

外部Agent无法接受平台强制策略的路径标记治理覆盖受限，敏感Profile拒绝接入。外部成果转发仍鉴权，跨协议任务ID和事件去重映射可核对。

### AC-028 事件、长期任务与资源控制

CubeSandbox资源专项归入本案例：create响应丢失、fork部分成功、clone清理失败、pause/delete并发、旧worker重试及节点失联。按持久ID核对VM、快照、卷、凭据和费用，unknown不变released；暂停释放计算不代表存储费用为零。

另覆盖create已成功但响应丢失且平台尚无sandbox ID：使用发送前持久化的operation关联发现，不能因查不到本地ID就重新创建或释放预占；无法查清时保留unknown与核对责任。

关联 REQ-OPS-001，对应 TASK-003、TASK-014、TASK-019。

重复Webhook、计划重试和补发事件只能创建预定数量的任务。定义时区、错过触发的补跑规则、并发上限和预算周期，重启后不丢失已确认事件，也不无限补跑。持续Agent按有界任务运行，心跳不能绕过截止时间。

测试租户资源竞争、队列积压、取消、回收失败和通知投递重试。报告队列等待、Outbox滞后、孤儿资源、租约抢占和成本归集。通知副作用使用独立操作ID。

## 评测实验矩阵

| 对照 | 固定条件 | 主要变化 | 需要报告 |
| --- | --- | --- | --- |
| 检索与组装 | 同任务、标签、模型和根预算 | 精确查询、混合检索、重排、压缩 | 召回@10 → 最终输入覆盖 → 证据支持 → 任务成功 |
| 记忆后端 | 同模型、相同可用历史、同预算 | 精确事实、摘要、分层记忆、增强读取 | 写入、读取、管理各阶段成本及跨新会话泛化 |

## 验收证据格式

每个 AC 记录版本、运行命令、环境、前置夹具、观察结果、判定与证据位置。状态使用 `planned / running / passed / failed / inconclusive`。实际实现前保持 `planned`，文档结构检查通过不能将软件案例改为 `passed`。

报告保留执行失败和待核对项，并说明是否阻止验收。触及授权、数据复活、重复副作用或接口不兼容的确定性反例必须修复，不能被平均质量分数抵消。试点数值门槛在最终集解封前确认并冻结。
