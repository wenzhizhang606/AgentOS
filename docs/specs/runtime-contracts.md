# AgentOS 运行契约规范

2026 年 11 月 17 日 · 设计基线草案 · 接口与示例待实现

本规范规定上下文、任务、委派、记忆、模块与评测数据之间的接口、状态和不变量。需求编号取自需求基线，技术设计使用本规范的对象名和状态名。外部接口以 HTTP `/v1` 表示，进程内模块使用相同的语义和校验规则。模型网关、工具与 MCP、沙箱、护栏及其他基础组件的详细接口见组件契约；这些组件沿用本规范的身份、任务、预算、取消和追踪语义。 [需求基线](../requirements/agentos-platform.md) · [技术设计](../design/technical-design.md) · [组件契约](component-contracts.md)

## 公共约定

| 项目 | 约定 |
| --- | --- |
| 标识 | `tenant_id`、`task_id`、`agent_version_id` 等均为不透明字符串，创建后保持稳定。资源定位包含租户。跨资源引用必须通过授权检查。 |
| 时间 | API 使用带 `Z` 的 UTC RFC 3339 时间。业务事实分别记录发生或生效时间与系统观察时间。 |
| 版本 | 可修改资源使用递增整数 `version`。不可变内容使用资源 ID、内容摘要和 Schema 版本定位。 |
| 金额 | 使用整数微单位 `amount_micros` 和显式 `currency`，例如 `CNY`。同一任务树采用一份固定价格表版本。 |
| 校验 | Schema 错误返回400，授权失败返回403，缺少或无权发现的资源返回404，并用内部审计记录实际原因。 |
| 并发 | 对可修改资源的写入携带 `If-Match` 对应的版本。不匹配返回409及允许披露的当前版本。 |
| 幂等 | 创建任务、委派、记忆提交、取消和费用结算携带幂等键。相同键和相同内容返回已有结果，相同键和不同内容返回409。 |
| 事件 | 事件包含 `event_id`、`task_id`、`sequence`、`type`、`occurred_at`、`attempt`。同一任务内 sequence 单调递增，消费方按 event_id 去重。 |

幂等键的命名空间包含租户、调用主体和操作类型，比较内容使用规范化请求摘要。键与操作结果在同一事务中持久化，保存期覆盖接口公布的最长重试和回调期限。超过保存期的请求由客户端显式创建新操作，业务写操作的唯一性同时由领域操作 ID约束。

## MySQL 持久化与准入边界

对应 REQ-DATA-001、REQ-OPS-001、REQ-MA-002、REQ-MA-003、REQ-GOV-001 和 REQ-OBS-001；数据库兼容与恢复映射 AC-017 / TASK-013，运行维护映射 AC-028 / TASK-003、TASK-019。

MySQL InnoDB 保存权威任务状态、租约、身份与资源策略版本、预算账本、记忆头指针、墓碑和 Outbox。对象存储保存较大载荷及确切序列化字节，检索索引是可重建的派生数据。数据库接口以 MySQL 8.4 兼容能力为基线，部署时固定具体发行版与补丁版本；升级至 9.7 LTS 等版本须通过同一契约与恢复验收，不能将 HeatWave 或其他产品的向量能力假定为普通 MySQL 能力。

准入是逻辑运行边界，可由与 worker 就近部署的执行点实现，不依赖管理台或配置编辑服务逐次转发。纯本地且不引入新受保护数据、外发或副作用的去重、排序、格式转换，不为每个函数创建 DispatchAttempt 或数据库锁。新的受保护读取、外部模型/工具发送、跨身份转发及持久状态变更仍遵守各自的权威检查；本地缓存和策略包不能独立授予新权限。纯计算复用的内容在外发或交付前仍复核授权。

| 边界 | 必须满足的契约 |
| --- | --- |
| 短事务 | 运行时连接显式使用 `READ COMMITTED`。对不变量的判断使用当前锁定读取、条件更新及唯一约束；普通读取不能替代并发校验。事务不得跨越模型、工具、外部检索、对象存储上传或其他网络调用。 |
| 队列领取 | worker 在独立短事务中使用 `FOR UPDATE SKIP LOCKED` 领取到期工作，持久化执行者、租约到期时间和递增 `lease_epoch` 后提交。领取条件与排序有匹配索引。跳过已锁行只用于可竞争的队列候选，不用于跳过权限、取消或预算校验。 |
| 租约与锁序 | 租约时间以数据库时间为准。复合事务按恢复代次头、稳定策略头、根预算、根至叶任务、审批、来源/发布清单、操作记录的顺序取锁，同类资源按稳定键排序。准入对策略头持共享锁，撤权等策略变更取排他锁；队列领取只持队列和任务锁，不在持锁期间再获取上游锁。 |
| 调用准入 | 在一次短事务内校验当前身份和策略、来源或记忆墓碑、任务与租约、截止时间及预算，创建唯一操作和费用预留，记录绑定快照摘要与策略版本的准入结果。只有已确认提交的准入操作可发送；无法验证权威状态或无法确认预留时不发送，并返回 `TRANSIENT_DEPENDENCY_FAILURE`。 |
| 授权读一致性 | 撤权、取消、墓碑和费用准入读取主库的当前权威状态。异步副本、旧事务快照或缓存不能独立授予执行资格。授权变更与准入锁定同一稳定策略头并检查递增epoch，不能锁定彼此不同的历史版本行。 |
| Outbox | 状态变化、领域事件、幂等结果及待投递工作在同一个 InnoDB 事务内写入。投递在提交后进行，采用至少一次投递和消费者去重。索引消费者按来源版本与删除代次处理乱序事件，不能用较早更新覆盖较晚删除。 |
| 失败恢复 | 死锁与锁等待超时均由应用显式回滚整个工作事务，再在原逻辑操作 ID 下有界退避重试。连接在提交阶段断开时先按幂等键查询主库确认结果；结果不明时保持待核对，不能重新预占或发起外部写入。 |

`READ COMMITTED` 本身不保证预算不超限或共享状态无冲突，正确性来自事务条件、约束和版本校验。`SKIP LOCKED` 也不保证公平领取，调度器须记录排队等待和租约重领，防止长期饥饿。旧 worker 即使取得外部响应，也不能绕过 fencing 校验提交结果。MySQL 对死锁和锁超时的默认回滚范围不同，本规范以上述整体回滚规则统一应用行为。[锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html) · [隔离级别](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html) · [错误处理](https://dev.mysql.com/doc/refman/8.4/en/innodb-error-handling.html)

最终发送准入以短事务提交的 DispatchAttempt 为线性化点。事务在统一锁序下检查稳定policy_epoch、根预算、祖先取消代次、任务与执行租约、审批和来源状态。角色、成员关系和资源ACL变化都递增对应policy_epoch。预审批、排队和提前预留不是最终发送准入。提交后到实际网络发送的间隙属于已准入在途范围，数据库提交与外部发送不构成原子事务。

每次实际发送有独立dispatch_attempt_id、短有效期和一次发送资格，过期不得发送；重发创建新尝试并重新准入，logical operation_id只标识同一业务动作。已准入请求在有效期内可能仍处于在途，撤权后尽力取消并阻止新的尝试，不能承诺收回已经外发的内容。外部结果未知时按其幂等能力决定核对，禁止盲目重发。

根任务和每个分支保存cancel_epoch与取消状态。最终准入检查所有有效祖先的当前值，异步取消通知只用于加快停止，不能成为正确性前提。任务树关系在一次运行内不可任意改挂，从而使祖先校验范围稳定。

### 灾备与恢复代次

部署方案必须记录备份位置、异地binlog保留、经验证的恢复水位及RPO/RTO。备份和日志只能恢复其覆盖的位置，不能推导缺失的最新撤权、墓碑、费用或发送记录。新调用与受保护内容读取在恢复期间关闭，恢复控制器取得新的平台恢复代次，旧worker、工作区租约和缓存失效。

恢复后重建可信授权及墓碑水位，核对恢复窗口内的外部效果、模型费用、沙箱租赁与未决发送。未找到记录不代表没有发生操作。对象和外置索引可能领先数据库恢复点，必须重核发布清单与引用。证据充分的范围分批恢复服务，日志缺口影响的范围保持隔离，不能宣称已恢复到最新状态。RPO/RTO数值在部署拓扑选定后冻结并通过恢复演练验收。[MySQL备份恢复边界](https://dev.mysql.com/doc/refman/8.4/en/recovery-from-backups.html)

任务身份、状态、租约、版本、可执行时间与预算等参与筛选、锁定和约束的字段使用独立列。JSON 用于扩展属性，必要的查询字段通过显式列或类型明确的生成列建立索引。请求幂等摘要、外发语义输入摘要、留存载荷摘要和可选传输字节摘要各标用途与算法，不能混用。MySQL JSON 会规范化内容，不能从数据库 JSON 重新序列化来证明原始字节相同；规范化规则由应用版本固定。[JSON 数据类型及索引边界](https://dev.mysql.com/doc/refman/8.4/en/json.html)

## 身份与作用域

对应 REQ-GOV-001、REQ-CTX-001 和 REQ-MA-001。

可信入口验证用户或工作负载身份后，由服务端生成 `ExecutionIdentity`，包含 `tenant_id`、`initiator_id`、`workload_id`、`delegation_id`、授权资源范围、允许操作、有效期及策略版本。客户端可请求目标项目和资源，服务端根据实际授权缩小执行范围。凭证通过运行时引用取得，模型输入使用必要的非敏感身份属性。

子任务的有效授权由当前发起人授权、父任务委派范围、子 Agent 能力上限及资源策略共同决定。企业、项目、用户、会话、任务、Agent 作用域表达数据归属，访问权限由资源策略明确授予。

检索过滤、按 ID 读取、缓存命中、摘要读取、产物转发和模型发送均执行同一授权语义。接入外部重排或模型服务时还校验该目标被授予的数据处理范围。权限变更更新策略版本并触发失效事件，消费入口同步检查当前策略版本。授权判定失败或所依赖版本失效时返回 `CONTEXT_STALE` 或 `FORBIDDEN`，调用方重新准备上下文。

撤权的生效点定义为授权模块提交新策略版本。之后获得最终发送或读取准入的动作使用新版本，之前已准入的在途动作按已提交顺序记录。审计分别保存策略提交、DispatchAttempt准入和实际发送时间，不能把三者宣称为同一原子事件。后续结果投递重新检查当前权限。

快照中保留的授权版本仅说明历史准入依据，不授予未来读取权。权限服务或权威数据库不可用时，新读取与调用不得以旧缓存授权继续；按依赖失败处理。已经提交且仍有效的准入与其后的撤权按已记录顺序归属，重试或过期准入重新检查当前权限。

## ContextSnapshot

对应 REQ-CTX-001、REQ-CTX-002、REQ-CTX-003、REQ-CTX-004 和 REQ-OBS-001。

`ContextSnapshot` 代表某一次模型调用实际准备发送的输入。创建后内容不可变，重排、补取、压缩或授权变化均生成新快照。

| 字段 | 含义和校验 |
| --- | --- |
| `snapshot_id`、`schema_version` | 快照身份与数据格式版本 |
| `task_id`、`step_id`、`attempt` | 绑定一次执行步骤和尝试 |
| `agent_version_id`、`strategy_version` | 固定 Agent 组合和上下文策略 |
| `identity_ref`、`authorization_revision` | 服务端身份引用与准备时的授权版本 |
| `source_refs` | 每项包含来源 ID、内容版本、有效时间、作用域、派生依据与类型 |
| `payload_digest`、`canonicalization_version` | 网关完成语义包装后输入的确定性哈希及规范化规则版本；包括消息顺序、指令、工具定义、输出格式、模态引用和内容版本；不是模型生成的摘要文本 |
| `payload_ref`、`stored_payload_digest` | 按保留策略实际保存的受控载荷引用及其独立摘要；未保存正文时为空，脱敏载荷不能用原始摘要校验 |
| `retention_mode`、`retention_policy_ref` | `full / redacted / metadata_only` 及保留策略版本、到期时间、脱敏规则和删除状态；清单与摘要也受授权及保留控制 |
| `capture_boundary`、`wire_digest` | 已验证的网关语义输入边界，以及可选的实际请求体字节摘要、编码与序列化器版本；不包含凭证，不宣称能观察供应商内部改写 |
| `selection_manifest_ref` | 选入、排除、压缩和缺口清单，包含原因及关联来源 |
| `budget` | 模型窗口、最大输入、预留输出、实际输入 Token、计数器版本及误差余量 |
| `valid_until` | 根据来源时效与授权有效期确定的再次检查时间 |
| `parent_snapshot_id` | 同一步补取或压缩产生新快照时指向上一个快照，可为空 |

对受管模型调用，`actual_input_tokens + reserved_output_tokens + safety_margin_tokens <= model_window_tokens`。实际输入包含消息包装、工具定义及适配器产生的内容。无法容纳必保留约束时返回 `CONTEXT_BUDGET_EXCEEDED`，运行模块可补充资源、调整任务或报告失败。

准备流程返回快照及待处理缺口。模型适配器发送前复核输入摘要、来源有效性和当前授权，然后记录快照 ID、准入时间和调用 ID。模型的 usage 回执与本地计数分开保存，用于费用核对。模型响应及工具结果归为新的任务事件，通过后续上下文准备进入下一次模型调用。

每次受管发送必须能够验证网关外发的语义输入与清单、`payload_digest` 一致。SDK 若继续修改语义内容，适配器须在修改后捕获并重新绑定快照；仅改变键顺序、转义或压缩的传输表示不冒充语义变化。语义等价性由适配器契约案例验证，完全不透明的外部 runtime 只能标记有限可观测，不能认证完整上下文治理。模型供应商内部提示与处理不属于可观测承诺。

正文留存由 Profile 与租户保留策略共同决定，默认不写入普通日志；需要完整回放的实验使用获准留存的数据和 `full` 策略。`redacted` 只展示脱敏视图，`metadata_only` 仅保存受控清单和摘要；二者不计完整回放覆盖。确需字节级诊断时额外保存适配器可观察的请求体字节并计算 `wire_digest`，不记录认证头。上传的实际留存对象校验 `stored_payload_digest` 后才登记数据库引用，孤立对象按保留策略回收。清单/摘要可追溯率与完整内容可回放率分别报告。

### 上下文模块接口

| 操作 | 输入 | 输出及失败语义 |
| --- | --- | --- |
| `prepare_context` | 服务端身份、任务与步骤、模型能力、预算、Agent 版本、资料引用 | `ContextSnapshot` 或明确错误，证据缺口随结果返回 |
| `resolve_context_item` | 身份、来源 ID及版本、读取目的 | 当前授权的内容与来源元数据，过期或不可访问时返回错误 |
| `inspect_context` | 身份、快照 ID | 授权范围内的输入、选择原因和来源链 |

检索、重排、压缩和组装是 `prepare_context` 内的可插拔接口。每种实现遵守同一输入输出格式，平台在共同接口测试预算、来源、权限和状态兼容性。

## Task 与执行状态

对应 REQ-MA-001、REQ-MA-002、REQ-MA-003 和 REQ-OBS-001。

`Task` 是具有目标、完成条件、执行预算和生命周期的工作单元。`root_task_id` 聚合协作任务树，`parent_task_id` 记录直接委派关系。任务的目标、完成条件和已选择的 Agent 版本在一次运行中固定。用户调整目标形成新的任务版本或后续任务，并记录与原任务的关系。

任务必需字段包括 `task_id`、`root_task_id`、`tenant_id`、`agent_version_id`、`goal`、`completion_criteria_ref`、`state`、`version`、`attempt`、`lease_epoch`、`deadline_at`、`budget_account_id`、`identity_ref`。结果记录 `result.status`、产物引用、未完成事项和错误。费用另用 `accounting_state` 表示 `pending` 或 `final`。

| 状态 | 含义 | 允许的后续状态 |
| --- | --- | --- |
| `queued` | 已持久化，等待取得执行租约 | `running`、`cancelled`、`timed_out` |
| `running` | 当前 worker 持有有效租约并执行 | `waiting`、`cancelling`、`succeeded`、`failed`、`timed_out` |
| `waiting` | 等待子任务、外部输入或重试退避，记录原因及唤醒条件 | `queued`、`cancelling`、`failed`、`timed_out` |
| `cancelling` | 取消已登记，正在停止新动作并收敛运行中的分支 | `cancelled`、`timed_out` |
| `succeeded` | 完成条件已验证并保存证据 | 逻辑终态 |
| `failed` | 已到不可继续的失败，或重试次数耗尽 | 逻辑终态 |
| `cancelled` | 取消流程已达到平台定义的收敛点 | 逻辑终态 |
| `timed_out` | 到达任务截止时间，禁止该运行启动新动作 | 逻辑终态 |

完成、取消和超时更新竞争同一个任务版本，先提交的终态生效。`result.status=partial` 表示存在部分成果，其能否满足成功条件由固定的业务完成条件决定。终态任务的成果和执行历史保留，后续重做创建关联的新任务。

### 重试与 worker 恢复

每次 worker 领取任务时获取递增 `lease_epoch`。写入步骤结果、提交共享状态以及启动外部调用都校验租约。租约过期后由调度器确认当前尝试状态，安排重试并递增 `attempt`。旧 worker 的迟到提交返回 `LEASE_LOST`。

状态更新、事件写入和待投递工作写入同一个数据库事务。后台投递器重试发送已提交工作，消费者以事件或操作 ID 去重。重试后相同的逻辑工具动作沿用原操作 ID，新的业务动作使用新 ID。

对外部写操作，适配器优先使用对方支持的幂等键。若发送结果未知且外部系统无法去重，操作状态记为 `unknown`，进入查询或人工核对流程，重试需依据核对结果决定。逻辑任务终态与外部副作用核对状态分别展示。

## Delegation 与协作消息

对应 REQ-MA-001、REQ-MA-002、REQ-MA-003 和 REQ-GOV-001。

委派记录包含 `delegation_id`、`parent_task_id`、`child_task_id`、`assigned_agent_version_id`、目标、完成条件、输入引用、输出 Schema、服务端派生身份、预算分配、截止时间、依赖任务和幂等键。子任务的截止时间与权限处于父任务授权范围内。

创建委派和子任务记录在同一事务内，随后投递执行事件。相同父任务、相同幂等键及相同请求只产生一个子任务。投递失败由事件重试恢复。

交接成果包含 `conclusion`、`evidence_refs`、`artifact_refs`、`unresolved_items`、`completion_status`、生成时的来源版本和实际上下文快照 ID。接收方读取成果时重新鉴权并检查依赖来源的当前有效性。需要原文时显式读取，并形成接收方的新上下文快照。

共享状态写入携带预期版本。不同子任务可先向各自结果空间提交，再由明确的汇总操作合并。合并规则随协作版本发布，冲突返回 `STATE_CONFLICT`，由汇总者依据规则补取资料或重新执行，避免静默覆盖。

暂停等待和取消均保留任务树。取消父任务后先持久化取消标记，再使尚未准入的子任务及工具操作失去执行资格，并向现有分支传播取消请求。任务是否完成依据可验证结果判断，文本中的“完成”字段需要和任务状态、产物校验一致。

取消或超时后的迟到结果保存为对应操作的核对事件，经过当前权限后用于审计。任务结果发布检查当前任务版本与状态，迟到响应不能将终态改回运行或成功。已经发生的费用照常结算，外部写入结果由操作核对流程确认。

## 统一预算与用量

对应 REQ-MA-003、REQ-OBS-001 和 REQ-EVAL-001。

每个根任务持有预算账户，包含 `limit_micros`、`reserved_micros`、`settled_micros`、价格表版本、最大并发和总截止时间。子任务、工具和后台记忆作业共享该账户。分配给子任务的额度作为子限额，实际调用在根账户只计一次。

每次DispatchAttempt准入前，按最大输出、固定价格表与工具报价预留成本，事务条件为 `settled + reserved + new_reservation <= limit`。费用归属于发送尝试，以提供商账户、dispatch_attempt_id和receipt_id去重；同一逻辑操作的两次已收费尝试必须分别记账。同一回执重复到达只结算一次，分段usage按增量键或明确累计版本结算。调用结果未知时保留该尝试预留，新尝试另行预留，不能复用尚未核清的额度。

上述比较与根账户更新、唯一预留记录和调用操作记录在同一个短事务内完成；不得先读取余额、提交事务后再扣减。结算同时更新账本与预留状态，重复回执不能重复释放额度。数据库不可用、事务冲突尚未解决或提交结果未知时，保持未准入；取得费用回执但未能结算时保留待结算状态并有界重试。子任务额度分配属于根账户内的约束，不增加根任务的可用总额。

提供商支持的输出或费用上限用于限制一次调用。无法提供确定上界的适配器必须声明预算控制是估计值，试点的硬预算对照选用具备可执行上限的适配器。超出估计的实际费用仍归入账本并触发停止新调用，报告记录预算偏差。

`hard_budget` 认证另附上界证明：输入/输出及工具计费单位、价格表版本、最大重试、沙箱硬租期、计费粒度和释放延迟假设。分别报告可控用量上限、固定价格表下的费用上限及供应商实际账单；通知告警不是执行上限。平台预留条件成立但提供商计费超出假设时记录违例并停用该硬预算认证，不掩盖费用或停止必要清理。

异步记忆生成、重排、压缩及索引更新在调度前预留费用，调用方任务在执行完成后可先进入逻辑终态，账户在全部关联作业结算后变为 `final`。基于单位成功任务成本的评测等待费用结算完成。跨任务共享费用使用评测配置固定的分摊规则。

成功任务可继续完成先前已登记并预留预算的后台记忆作业，其作业截止时间处于根任务的预算有效期内。取消或超时阻止待执行的业务推理、提取和索引构建作业，并要求运行中的作业在下一次提交前检查取消状态。

资源终止、撤密钥、墓碑传播、索引删除、费用与外部结果核对属于必要维护作业，使用独立控制面执行配额，在任务终态、截止时间或业务预算耗尽后仍须收敛。创建沙箱时预留到硬租约到期的费用与可估算清理上限，计费持续至提供商确认释放。维护费用仍归因原任务并进入项目总成本，异常超额如实记录为预算违例，不能为保持账面上限停止清理。不能提供可执行费用上限的后端不进入硬预算Profile。

## MemoryRevision 与知识变更

对应 REQ-MEM-001、REQ-RAG-001、REQ-CTX-003 和 REQ-GOV-001。

记忆条目由稳定的 `memory_id` 表示，每次修改产生独立 `revision_id`，保存 `fact_key`、作用域、原始证据、写入者、提取器版本、确认状态、`valid_from`、`valid_to`、`observed_at`、`supersedes_revision_id` 和内容摘要。读接口接受当前或指定业务时点，并在当前权限下决定可访问内容。

另记录 `information_kind`（业务观测、用户陈述、推断偏好、事件摘要、经验候选）、`authority_source_ref`、时效规则及是否需要当前业务复核。相似度只决定相关性，不能改变权威等级。MySQL是平台记录的权威存储，订单/库存等事实仍以对应业务系统为准；权威接口不可用时历史记忆只能标明观察时间或返回未知，不能自动作为当前事实执行动作。模型生成经验需经候选评测，不能直接修改平台权限或业务规则。

| 修订状态 | 含义及转换 |
| --- | --- |
| `candidate` | 待写入策略检查的提取结果，通过后变为 `active`，未采用时可撤回为 `retracted` |
| `active` | 当前可参与读取的修订，后续有效修订接替后变为 `superseded`，删除或撤回变为 `retracted` |
| `superseded` | 已被新修订取代，历史时点查询依当前权限和有效时间取回；修订被撤回时转为 `retracted`，命中条目墓碑时立即不可读 |
| `retracted` | 已撤回或删除，普通查询排除该内容，受控审计按保留策略提供元数据 |

同一作用域和事实键的当前头指针由版本比较更新。事实冲突先比较来源、有效时间及确认状态，无法确定时保留候选冲突供读取方识别。语义相似度可用于去重，冲突更新须进入修订判定。

更正、删除与撤权操作提交修订状态和失效事件。读取路径检查当前状态，从而阻止旧缓存及旧索引内容进入后续上下文。后台工作清理派生摘要、检索索引和缓存，并记录每个受影响目标的处理状态。操作返回 ID供调用方追踪“已接收”和“在线派生内容处理完毕”。

记忆级撤回与单次修订更正具有不同范围。`POST /v1/memories/{memory_id}/retract` 撤回整个条目：同一事务写入该 `memory_id` 的墓碑、递增失效代次、停用当前头并写入派生失效 Outbox。墓碑覆盖全部 `candidate`、`active`、`superseded` 修订，以及由这些修订产生的摘要、缓存、索引和旧快照中的对应内容；禁止通过历史时点、直接 revision ID、旧载荷引用或旧授权快照绕过墓碑。普通读取只返回仍可访问的内容或明确不可用，审计按保留策略提供元数据。

条目墓碑是同步生效的权威拒绝条件，逐修订标为 `retracted` 及派生正文清理可异步完成。每个提取、索引和摘要作业携带读取时的来源版本及失效代次，发布前再次检查；删除前启动的作业不能在删除后复活记忆。幂等重放撤回返回原操作，不重复创建新代次。备份恢复或模块范围恢复不能清除已生效墓碑；确有重新建档需求时按当前授权和新的有效证据创建关联的新条目，原条目的拒绝条件保留。单次修订撤回仅影响指定修订及其派生内容，不能被解释为整个条目的删除成功。

外置索引写入使用不可变的来源版本、索引代次和嵌入版本标识。内容先写入暂存代次，确认完成后，在MySQL以预期来源版本、失效代次和墓碑条件CAS更新已发布清单。检索只接受当前清单中的版本。删除或更新先提交使旧发布CAS失败，迟到的索引物理写入只能成为待清理的未发布数据，不能覆盖新代次或重新变成可读内容。MySQL与检索后端之间不宣称分布式原子事务。

知识文档采用同样的来源版本与派生关系约定。原文更新后生成新文档版本及索引版本，检索片段携带原文段落位置。删除内容的原文与快照载荷遵守保留策略，保留元数据与正文保留期限分别管理。

## 模块与发布契约

对应 REQ-MOD-001、REQ-MOD-002 和 REQ-RSI-001。

模块发布清单至少包含名称、不可变版本、实现摘要、接口名与主版本、配置 Schema、输入输出 Schema、请求能力、状态 Schema、兼容范围和迁移说明。每个实现明确错误语义、取消支持、费用上限、幂等能力及依赖。平台核验清单后派生实际授予能力。

认证记录绑定 Profile、runtime版本、插件与配置摘要、协议版本、操作系统/沙箱环境、策略类别和验收报告。单模块通过不授予任意组合可用资格；别名更新或声明能力扩大必须重新检查受影响范围。只对 certified 组合开放生产路由，experimental 组合进入独立实验入口。单模块契约全测，组合按交互风险选择覆盖强度，权限、预算、取消和恢复关键路径额外注入故障，不能把两两覆盖当作全部交互保证。

Python 与 C++ 共享语言无关的边界 Schema 和错误语义。RPC 必须保持金额整数的完整精度、标识、UTC时间、版本、截止时间、操作ID及取消代次；若使用 ProtoJSON，int64 按其十进制字符串规则编码。服务端验证授权、范围和状态，类型标注或编译通过不能代替运行时验证。C++ 计算组件不直接写平台权威表，不独立重试业务副作用；native异常映射为错误或worker失联，迟到结果仍经租约/取消校验。

`AgentVersion` 固定模型、上下文策略、工具、记忆和协作实现的清单与内容摘要。新任务选择发布版本，已有任务按自己的版本恢复。兼容迁移执行前保存可恢复检查点，迁移成功后原子切换头指针。迁移失败时保留检查点与失败证据，由恢复流程决定重试或回退。

MySQL 的原子 DDL 不等于事务式 DDL。Schema 变更、数据回填和发布指针切换不能假定处于同一个可回滚事务。迁移依次完成兼容 Schema 扩展、可重入的数据回填、完整性与兼容性校验，再以短事务和预期版本切换数据或发布头；旧格式收缩延后到旧运行不再依赖它。每个阶段保存检查点、输入输出版本和结果，失败时保持可用旧读路径，不能宣称普通事务已撤销 DDL。[MySQL 原子 DDL 边界](https://dev.mysql.com/doc/refman/8.4/en/atomic-ddl.html)

范围恢复记录效果范围、受影响键、变更前后版本、检查点及恢复操作 ID。若当前状态仍等于变更 A 产生的预期后版本，可用 CAS 恢复；若已有合法变更 B，则先判定效果范围是否重叠。只有具有明确合并规则且通过约束校验的补偿才能在当前版本上保留 B 并撤销 A；不可逆或无法安全合并的重叠变更返回 `STATE_CONFLICT`，进入协调流程并保留当前状态。任何恢复都不得直接覆盖整份旧快照而丢失 B，不得回退权限撤回、墓碑或已结算费用。恢复操作幂等，重复请求不重复补偿；真实外部副作用使用领域补偿及结果核对，不由插件或数据库版本切换隐式撤销。

接口主版本变化需要新适配器或显式迁移。增加可选字段可在兼容版本中发布，已有必填字段的含义变化需要新主版本。原始模块清单和 Agent 版本保持可查，受数据保留策略约束的内容通过引用管理。

## EvaluationResult 与候选发布

对应 REQ-EVAL-001、REQ-EVAL-002 和 REQ-RSI-001。

一次评测固定 `evaluation_id`、候选与基线版本、任务集和数据快照摘要、评分规则版本、模型池、预算、并发、重复次数、随机性设置及费用口径。每个案例记录运行 ID、预期完成条件、证据标签版本、实际结果、指标分子分母、判分状态及评分证据引用。

评测配置另固定主要与次要指标、实验单位及聚类规则、样本量依据、显著性/功效、非劣界、多重比较与停止规则。可恢复故障类别在测试前声明；安全拒绝、正确核对和业务成功分列。完整上下文质量评分需获准访问真实语义载荷；缺失或已脱敏到无法判分的记录标为不可评，不伪造完整覆盖，缺口影响验收结论。

判分状态为 `pending`、`scored`、`error`，执行失败通过业务规则计失败。判分器故障保留为待评分并补评。汇总结果记录有效样本量、覆盖率、分层指标、任务级配对置信区间、成本结算状态以及验收结果 `pass`、`fail` 或 `inconclusive`。

候选生成者使用开发集及其轨迹，独立验收执行者持有最终验收集访问权。模块候选保存父版本、差异、方法或论文来源、实验预算和恢复验证结果。发布依据已冻结的验收配置，对需要统计支持的收益，区间或覆盖不足时标为 `inconclusive`。

## HTTP 入口与错误处理

| 入口 | 用途 | 主要语义 |
| --- | --- | --- |
| `POST /v1/tasks` | 创建根任务 | 必填 Idempotency-Key，服务端生成身份与预算账户，返回202及任务引用 |
| `GET /v1/tasks/{task_id}` | 读取任务状态 | 返回执行状态、版本、结果引用、费用结算和待核对副作用 |
| `POST /v1/tasks/{task_id}/cancel` | 请求取消 | 幂等，按当前状态返回202或已存在终态 |
| `POST /v1/tasks/{task_id}/delegations` | 委派子任务 | 服务端收窄身份和预算，在事务内创建委派与子任务 |
| `GET /v1/context-snapshots/{snapshot_id}` | 检查实际输入 | 读取时鉴权，按内容保留和失效状态返回可见数据 |
| `POST /v1/memories/{memory_id}/revisions` | 新建记忆修订 | 必填幂等键及预期版本，写入策略产生候选或生效修订 |
| `POST /v1/memories/{memory_id}/retract` | 撤回整个记忆条目 | 同步提交覆盖全部历史修订的墓碑、停用头指针及派生失效事件，返回操作 ID |
| `GET /v1/operations/{operation_id}` | 检查异步操作 | 返回当前状态及受控可见的失败或未完成目标 |
| `GET /v1/evaluations/{evaluation_id}` | 读取评测 | 访问权与数据集权限绑定，返回版本、覆盖和验收结果 |

| 错误码 | 调用方处理 |
| --- | --- |
| `INVALID_ARGUMENT` | 修正输入后提交新请求 |
| `FORBIDDEN`、`RESOURCE_NOT_FOUND` | 检查身份与资源引用，向任务记录明确失败原因 |
| `VERSION_CONFLICT`、`STATE_CONFLICT` | 重新读取授权范围内的状态，按业务规则合并后重试 |
| `IDEMPOTENCY_CONFLICT` | 为新的逻辑请求使用新键，原请求结果保持可查 |
| `CONTEXT_STALE` | 重新准备上下文并复核来源和权限 |
| `CONTEXT_BUDGET_EXCEEDED`、`BUDGET_EXHAUSTED` | 根据任务策略减少范围、补充预算或结束任务 |
| `LEASE_LOST` | 当前 worker 停止提交，由调度器负责恢复 |
| `DEADLINE_EXCEEDED`、`CANCELLED` | 保存已有成果及费用，停止新动作 |
| `EXTERNAL_OUTCOME_UNKNOWN` | 进入外部操作核对，保留原操作 ID与费用预留 |
| `SNAPSHOT_CONTENT_UNAVAILABLE` | 报告可回放范围，按现有来源准备新的运行 |
| `TRANSIENT_DEPENDENCY_FAILURE` | 关闭新的调用准入，在剩余截止时间、次数与预算范围内退避重试；提交结果未知时先按原操作 ID 核对 |

所有错误响应采用以下结构，`retryable` 只表示按当前策略允许自动重试。

```json
{
  "error": {
    "code": "CONTEXT_STALE",
    "message": "Source revision changed before model dispatch",
    "request_id": "req_01",
    "retryable": true,
    "details": {
      "snapshot_id": "ctx_01",
      "required_action": "prepare_context"
    }
  }
```

## 回放与验收边界

回放模式有两种。输入重建从仍获授权且完整留存的快照恢复网关外发语义输入，并按原规范化版本核验摘要；字节重建仅在保存了原请求体时成立。对照执行在隔离环境使用相同输入和指定策略版本重新运行，工具可由固定数据快照或受控替身提供。脱敏、未留存或已删除正文返回 `SNAPSHOT_CONTENT_UNAVAILABLE`，不冒充原始回放。外部实时工具重新调用记录为新的执行，关联原运行，费用和副作用单独记账。

来源被更正、撤权或删除后，快照检查和回放继续经过当前授权与保留策略。无法取得完整原始载荷时报告内容不可用，保留已授权的元数据和实验配置用于诊断。模型版本、随机性与外部数据差异写入评测结果，输入可重建与输出复现分别验收。

契约验收覆盖真实入口、重复请求、跨作用域读取、并发更新、发送前撤权、worker 租约丢失、取消竞争、未知外部写结果、预算并发预留、派生删除、版本恢复及费用最终结算。每个案例绑定需求编号，并在开发任务中记录实际实现和运行证据。 [验收规范](acceptance.md)

MySQL 验收另覆盖队列抢占与饥饿、死锁、锁超时、提交响应丢失、Outbox 重复与乱序、主库故障时准入关闭、恢复后墓碑重放、JSON 与原始字节哈希差异，以及多阶段 DDL 迁移中断。记忆删除须包含 `superseded` 修订直接读取、历史时点读取和旧快照回放；恢复须分别验证无后续写入的 CAS 成功、可安全合并的独立 B 保留，以及重叠不可逆 B 的冲突协调。监控记录领取等待、租约重领、死锁重试、Outbox 延迟、索引新鲜度、撤权与删除在线传播、恢复耗时和未结算操作数；实际阈值与证据归入 AC-017、AC-028 及关联业务验收。
